# 多世界配置指南

本文说明竹取合战在多世界服务器（如使用 Multiverse 等世界管理插件）上的配置方式，
覆盖插件配置项、模板世界与房间世界的约定，以及常见问题排查。

> 目标读者：服务器管理员。全部配置项都在 `plugins/TaketoriKassen/config.yml`，
> 修改后执行 `/taketori reload` 生效。

---

## 一、世界的三层结构

| 世界 | 谁创建 | 位置 | 生命周期 |
| --- | --- | --- | --- |
| **大厅世界** | 管理员（任意世界，通常就是主世界） | 服务器根目录（正常世界） | 永久；出生点/范围用指令写入 `lobby.yml` |
| **模板世界** | 管理员制作，放进 `moonmaps/` | `plugins/TaketoriKassen/moonmaps/<模板名>/` | 永久模板；运行时不需要加载 |
| **房间世界** | 插件按需复制 | 服务器根目录 `kassen_<序号>` | 一次性：创建 → 对局 → 结算后自动卸载并删除 |

多房间并发时，每个房间独占一个 `kassen_N` 世界——这是消息、实体、掉落物互不干扰的物理基础。

## 二、插件配置项

### 1. 消息播报范围：`worlds.broadcast-scope`

```yaml
worlds:
  broadcast-scope: world   # 默认
```

- `world`（默认）：消息只发给"消息所属世界"的玩家——
  对局播报 → 对局世界，房间播报 → 房间世界，大厅播报 → 大厅世界；
- `all`：全服广播（旧行为，多世界服务器不推荐）。

房间世界是动态的，播报范围按房间的出生点 / 基地 / 刷新区 / 等待点所在世界集合计算，
无需逐房间配置。

### 2. 进服送大厅：`lobby.takeover-worlds`

```yaml
lobby:
  takeover-worlds: []      # 默认：只接管大厅出生点所在的世界
```

- 留空（默认）：玩家从大厅世界进服才传送到大厅，从资源世界、其他玩法世界进服位置不变；
- `["*"]`：接管所有世界（旧行为）；
- 显式列出：`["world", "world_nether"]`。

### 3. 大厅保护：`lobby.protect`

`true`（默认）时，位于大厅范围（`lobby region`）内的玩家不掉血。
范围用 `/taketori lobby pos1 | pos2 | setregion` 划定。

## 三、模板世界（moonmaps）

### 1. 目录约定

```
plugins/TaketoriKassen/
└─ moonmaps/
   ├─ kaguya/            ← 一个模板 = 一个完整的世界文件夹
   │  ├─ level.dat
   │  ├─ region/
   │  └─ ...
   └─ <其他模板名>/
```

- `moonmaps/` 目录首次启动自动创建；
- 一个模板 = 一个世界文件夹，模板名即文件夹名（arenas.yml 里同名的条目就是它的定义）；
- **运行时模板不需要被加载**——插件只读取文件夹做复制，坐标数据保存在 arenas.yml。

### 2. 制作模板的两种方式

**方式 A：外部建好，拷入**

1. 在任意世界（Multiverse 创建或单机制作）建好合战地图；
2. 停服（或先卸载该世界），把整个世界文件夹复制到
   `plugins/TaketoriKassen/moonmaps/<模板名>/`；
3. 起服后 `/taketori arena create <模板名>`（创建定义并选中）→
   `/taketori moonmap load <模板名>`（复制成编辑世界 `k_tpl_<模板名>` 并传送进去）
   → 用选区锄/指令划定要素 → `/taketori moonmap unload <模板名>`（保存写回并卸载）。

**方式 B：直接在编辑世界里建图**

1. `moonmaps/` 里先放一个任意世界文件夹（或从方式 A 拷入的半成品）；
2. `moonmap load <名>` 加载编辑世界；
3. 在编辑世界里用 WorldEdit / 手工搭建地形，并用指令划定要素；
4. `moonmap unload <名>` —— 编辑世界存盘后**写回 moonmaps/**（失败自动回滚），并删除根目录的编辑副本。

### 3. 模板就绪条件

`/taketori moonmap list`（或 `arena list`）逐项检查，模板必须凑齐：

- 至少 1 个月人刷新区（`arena setminion`，可多个，标签 normal/mixed）；
- 双方各 N 个基地（`arena setbase red|blue`）；
- 双方出生点（`arena setspawn red|blue`）；
- **等待出生点**（`arena setwait`，动态房间必备）；
- 可选：道具点（`setloot`）、PVE 据点（`setoutpost`）。

缺什么会在 `missingHint` 里直接列出。模板还可以 `enable/disable`（关闭后玩家不能用它创建房间）。

## 四、房间世界（kassen_*）

- 房间世界由插件在玩家创建房间时**异步复制**生成，命名为 `room.world-prefix`（默认 `kassen_`）+ 自增序号；
- 复制时跳过 `session.lock`，加载后自动设置：昼夜/天气/自然刷怪/火焰蔓延关闭、死亡保留开启、关闭自动保存；
- 结算完成、玩家回到大厅后自动卸载并**删除文件夹**（删除失败延迟重试）；
- **服务器崩溃残留**：下次启动时插件自动清理根目录残留的 `kassen_*` 与 `k_tpl_*` 世界（先卸载后删除）。

### 与 Multiverse 的相处

1. **不要把 `kassen_*` / `k_tpl_*` 世界 import 进 Multiverse**——它们是临时的，插件自己管理；
   若被 MV 自动导入，插件启动清理会卸载并删除。
2. **Multiverse 的重生设置不影响参赛者**：对局内死亡由插件的 `PlayerRespawnEvent` 接管
   （回己方出生点 / 旁观倒计时），优先级高于 MV 的重生规则。
3. 模板地图建议关闭 `doDaylightCycle`、`doWeatherCycle`、`doMobSpawning`、`doFireTick`
   （`mv modify set` 或世界内 `/gamerule`），加载房间后插件会再统一设置一遍，双保险。
4. 若使用 Multiverse-Inventories 等背包隔离插件：对局内的背包由插件全量封存/返还，
   与 MV 的按世界背包不冲突（对局中插件持有的是"封存快照 + 对局装备"两套数据）。

## 五、常见问题排查

| 现象 | 排查 |
| --- | --- |
| 创建房间提示"还没有可用的月面模板" | `moonmaps/` 里没有世界文件夹，或 arenas.yml 没有同名的启用模板；用 `moonmap list` 核对 |
| 创建房间提示"模板未就绪" | 按 `missingHint` 补齐：刷新区 / 基地 / 出生点 / 等待点 |
| 创建房间提示"找不到 level.dat" | `moonmaps/<模板>/` 不是一个世界文件夹（缺 level.dat 与 region/） |
| 玩家从别的世界进服没被送到大厅 | 该世界不在 `lobby.takeover-worlds` 且不是大厅世界（默认行为） |
| 消息串到别的世界 | `worlds.broadcast-scope` 被改成了 `all` |
| 对局播报别的房间看不到 | 正常——每个房间独占世界，播报只发本房世界；需要全服可见就改 `broadcast-scope: all` |
| 崩溃后根目录多了 `kassen_*` 文件夹 | 下次启动自动清理；也可手动删除 |
| 对局进行中想卸载某个世界 | 先 `/taketori match stop <房间id>`，等结算回收后再卸载 |

**自检**：`/taketori doctor` 会一次性报告播报范围、进服接管白名单、模板与房间状态，
多世界问题优先用它定位。

## 六、推荐的多世界部署示例

```
world            （主世界 / 大厅：lobby spawn + region，takeover 默认只接管这里）
world_nether     （原版下界，不接管、不播报）
kaguya           （可选：模板源世界；建好后拷入 moonmaps/ 即可删除）
kassen_1 ...     （插件自动创建/删除的房间世界，无需管理）
k_tpl_kaguya     （编辑模板时的临时副本，unload 后自动删除）
```

- `config.yml`：`broadcast-scope: world`、`takeover-worlds: []`、
  `room.max-rooms` 按服务器规模调整；
- Multiverse：正常管理你的主世界与资源世界即可，`kassen_*` / `k_tpl_*` 交给插件。
