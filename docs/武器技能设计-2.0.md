## 零、阅读须知：伤害口径与"不超标"的判定方法

### 0.1 伤害基线（沿用 `weapons.yml` 头部注释的定义）

全套铁甲 = 15 点护甲 → 减伤 `15/(15+8) ≈ 65.2%`。

```
实际伤害 ≈ 配置伤害 × 0.352
想"N 击击杀 20 血铁甲目标" → 配置伤害 ≈ 57.4 / N
```

本文档所有 `damage` 都是**配置值**，判定口径固定为「对穿保护 II 全套铁甲的 20 血玩家」。

| 配置伤害 | 对铁甲实际伤害 | 对铁甲击杀所需次数 | 对无甲 40 血月人 |
| --- | --- | --- | --- |
| 6 | 2.1 | 10 | 7 次 |
| 8 | 2.8 | 8 | 5 次 |
| 10 | 3.5 | 6 | 4 次 |
| 12 | 4.2 | 5 | 4 次 |
| 14 | 4.9 | 5 | 3 次 |
| 16 | 5.6 | 4 | 3 次 |
| 18 | 6.3 | 4 | 3 次 |
| 20 | 7.0 | 3 | 2 次 |
| 22 | 7.7 | 3 | 2 次 |

> **单次伤害上限自我约束：22.0**（与现有全表最高的 `mikado_konbo` 近战模式震地 22.0 持平）。
> 不为任何新武器设计超过 22.0 的单发伤害；`ConfigValidator` 的告警阈值是 40.0，本文档主动留出约 45% 的余量。

### 0.1.1 一个必须说清的口径细节

`weapons.yml` 的基准注释把"全套铁甲 + 保护 II"统一按 **0.352** 折算，本文档的所有"对铁甲实际伤害"都沿用这个口径，以便与现有 17 把武器**逐项可比**。

需要知道的是：如果严格按原版公式把保护 II（每件 4% 减伤、按件乘法）也算进去，真实倍率约为 **0.252**（15 点护甲减 34.8%，保护 II 再减约 28.4%，15×0.652×0.716 ≈ 7.0 有效护甲）。也就是说：

- 本文档的"实际伤害"数字是**偏保守口径下的高估**；
- 按严格口径，所有新武器的实际伤害比表里更低（例如 22.0 配置值对铁甲实际约 5.5 而非 7.7）；
- 反过来，只要与现有武器在**同一口径**下比较不超标，两种口径下的结论一致，而且严格口径更宽松。

这个差异同时也说明：为什么"组合技兑现伤害 ≤ 9.5 实际伤害"这个约束是安全的 —— 它是用最严苛的那个口径算出来的。

### 0.2 判定"不超标"的四个维度

1. **单发伤害**：基础伤害（不含任何连携加成）不超过 22.0（现有上限）；连携加成后的等效伤害不超过 22.0 × 1.6 = 35.2 配置值（按基准口径约 12.4 实际伤害，打不穿满血）。
2. **冷却** 主动输出循环 ≤ 8 秒，控场 12~14 秒，大招 18~22 秒（现有最高 22.0 秒）。
3. **范围** 圆形 AoE 半径 ≤ 5.5（现有最高 5.5），扇形角度 ≤ 130°（现有最高 130°）。
4. **持续时间** 硬控（定身）≤ 2 秒，软控（减速）≤ 6 秒，易伤标记 ≤ 5 秒，破甲 ≤ 6 秒。
5. **额外约束**：任何组合技的"前置条件"都必须由本角色自己的武器提供，且**前置技能不能同时是高伤害技能**（保证"先控后爆"的节奏成本真实存在）。

2.0 版就是围绕这五个空档 + 现有机制做的体系化补完，而不是重新发明数值。

## 三、组合技（连携）设计

> **统一规则**（贯穿全部 8 组）：
> 1. 每组组合的**前置条件**都由**本角色自己的武器**提供，不依赖队友、不依赖月人。
> 2. 前置技能**必须是低伤或纯控制技能**（最高 16.0 配置值），收益技能是对应的爆发技能。
> 3. 两种"消费型"加成**不叠加**（同一目标只取其中一层，代码里按乘法顺序结算一次，见 5.2）。
> 4. 标记/破甲的持续时间（4~6 秒）就是连招窗口；窗口内没接上就只是普通收益。

### 组合 1 ｜辉夜：月铃 → 火箭锤（易伤兑现）

| 项 | 内容 |
| --- | --- |
| 武器组合 | `kaguya_bell`（前置）+ `kaguya_hammer`（兑现） |

| 组合 4 雷（破甲 0.15/0.22） | 10.0 × 破甲系数 ≈ 12.6 等效 | ≈ 5.1 | 是（8s CD） | 否 |
| 组合 5 八千代（冰冻 ×1.4） | 19.6 | 6.9 | 是（7s CD） | 否 |
| 组合 6 真实（标记 ×1.6） | 25.6 | 9.0 | 是（4s CD，前置便宜故兑现也弱） | 否 |
| 组合 7 宅公（减速 ×1.6） | 24.0 | 8.4 | 是（常态减速即可，门槛最低） | 否 |
| 组合 8 芦花（减速 ×1.6） | 12.8（但 1.8 攻速） | 4.5 | 是（3s CD 缚足弹） | 否 |

**核心结论**：全部 8 组组合技的兑现伤害都落在 **8.4 ~ 9.5 实际伤害** 区间，即"打完一套组合技，对手还剩 40% 以上血"。没有任何一组能单靠一次连招击杀满血铁甲目标 —— 这是"不超标"最直接的证据。

### 4.3 冷却预算对比

| --- | --- | --- | --- |
| 主输出（左键 / 右键点射） | 0 ~ 4.0s | 0 ~ 7.0s | 只有 `mark_apply`（挂标记）取 7~10s，因它服务全队 |

## 五、新增技能类型清单

> 共 **5 个新类型**。每个类型都给出：行为、判定细节、参数键、取值域、实现要点。
> 所有新类型都必须同时登记到两处，否则构建的 `checkParamKeys` / `WeaponYamlCheck` 会失败：
> ① `src/main/java/com/taketori/kassen/config/ConfigValidator.java` 的 `ALLOWED_PARAMS`

### 5.1 `mark_apply` —— 易伤标记施加

**行为**：以自身为圆心（`radius` 格）或对视线内最近目标（`radius` 视为射程，`radius ≥ 8.0` 时自动走"视线射线"分支），造成 `damage` 伤害并叠加一层**易伤标记**。

**判定细节**

1. 目标筛选复用 `ShockwaveSkill` 的规则：`LivingEntity`、非自己、非旁观者、**同队受友伤保护者跳过**（复用 `MeleeSmashSkill.isProtectedTeammate` 的判断，避免"给队友挂易伤"）。
2. 标记通过 `plugin.states().mark(uuid, mark-ticks, mark-bonus)` 写入 —— 复用现有 `CombatStates.Mark`，并由 `CombatListener.onMarkedDamage` 自动放大后续所有伤害。**不新增事件监听**。
3. 标记是**覆盖**语义（`marks.put`），不叠加倍率；重复施放只刷新时长。这保证了"标记强度恒定"，不会因连续挂标而变成无限增伤。
4. 命中 0 个目标时走 `skill.shockwave-none` 同款提示（动作栏），避免"不知道有没有生效"。
5. 可选 `invisible-ticks > 0` 时给自己挂隐身（`PotionEffectType.INVISIBILITY`，`ambient=true`），用于远程角色重新找角度。

| 参数键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `damage` | double | 4.0 | 直接伤害 |
| `radius` | double | 3.0 | ≤ 7.0 为圆心半径；≥ 8.0 为视线射线射程 |
| `angle` | double | 45.0 | 射线模式下的半角（度） |
| `mark-bonus` | double | 0.2 | 易伤比例（0.2 = +20%） |
| `mark-ticks` | int | 80 | 标记时长（tick） |
| `invisible-ticks` | int | 0 | 自身隐身时长 |
| `slow-duration` | int | 0 | 附加减速时长 |
| `slow-amplifier` | int | 0 | 附加减速等级 |
| `slow-type` | string | SLOWNESS | 药水效果名（走 `VersionAdapter.potionEffect` 校验） |
| `particle` / `sound` | string | END_ROD / BLOCK_AMETHYST_BLOCK_CHIME | 表现 |

**实现要点**：新类 `paper/skill/impl/MarkApplySkill.java`，`type()` 返回 `"mark_apply"`；在 `TaketoriPlugin` 注册段加一行 `registry.register(new MarkApplySkill(this));`。

### 5.2 `armor_break` —— 破甲 / 削防

**行为**：范围（`radius`）伤害 + 击飞，并给目标挂**破甲层数**；破甲期间目标受到的伤害按 `armor-pierce` 提升。

**判定细节**

1. 破甲状态复用 `CombatStates`，但**不放进 `Mark`**（否则会顶掉乃依的易伤标记，两者必须能共存）。新增一个 `Map<UUID, ArmorBreak>`：
   ```java
   public record ArmorBreak(long untilMillis, double pierce, int stacks) { public boolean expired() {...} }
   public void armorBreak(UUID uuid, int ticks, double pierce, int stacks) {...}
   public ArmorBreak armorBreak(UUID uuid) {...}         // 惰性过期清理
   // sweepExpired() 里一并 removeIf 过期项；clear()/clearAll() 一并清理
   ```
2. 伤害放大在 `CombatListener` 里新增一个监听器（与 `onMarkedDamage` 并列，`EventPriority.HIGH`）：
   ```
   最终伤害 = 基础伤害 × (1 + markBonus) × (1 + min(armor-pierce, 0.30))
   ```
   - 两个乘区**独立**、可叠加（这是刻意的：乃依标记 + 帝破甲是跨角色的团队配合彩蛋，但单人做不到，因为没有任何角色同时拥有两者）。
   - `armor-pierce` 硬上限 **0.30**（代码里 `Math.min(0.30, pierce)`）：即最多把对铁甲的减伤从 65.2% 降到 51.2%，配置 22.0 的伤害对铁甲从 7.7 提到 10.7，**不会出现"一击半血"**。
   - 与 `shield_guard` 的 `armor-pierce` 共用同一实现：`armor_break` 技能写状态，`shield_guard` 写防御窗口，结算时取两者最大值（`Math.max`），不做连乘。
3. 层数 `debuff-stacks` 只用于**提示与强度递增的语义**（本文档中 `stacks` 不改变倍率，仅让动作栏显示"破甲 ×2"）；真正的强度由 `armor-pierce` 决定。这样实现简单、不会出现"叠 10 层破甲秒人"。

| 参数键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `damage` | double | 10.0 | 范围伤害 |
| `radius` | double | 3.5 | 圆形半径 |
| `knockback` | double | 0.6 | 水平击退 |
| `launch` | double | 0.4 | 向上击飞 |
| `min-falloff` | double | 0.5 | 边缘最低伤害比例 |
| `armor-pierce` | double | 0.15 | 伤害提升比例，硬上限 0.30 |
| `debuff-ticks` | int | 100 | 破甲时长 |
| `debuff-stacks` | int | 1 | 层数（提示用） |
| `slow-duration` / `slow-amplifier` | int | 0 / 0 | 附加减速 |
| `particle` / `sound` | string | EXPLOSION / BLOCK_ANVIL_LAND | 表现 |

**实现要点**：新类 `paper/skill/impl/ArmorBreakSkill.java`；`CombatStates` 增加 `ArmorBreak` 记录与读写方法；`CombatListener` 增加破甲放大监听器；动作栏提示复用一个新消息键 `skill.armor-break`（`messages.yml` 会自动回填默认值，见 7.2）。

### 5.3 `echo_consume` —— 标记/破甲兑现

**行为**：不做范围判定，**只是给一个已有技能包一层"条件加成"**。设计上它作为 `melee_smash` / `projectile` / `shockwave` / `mirror_burst` 的**同级替代类型**出现，因此只需要支持单目标近战与弹体两种形态。

**判定细节**

1. 由于它替代的是"带前摇的爆发技能"，判定逻辑与 `MeleeSmashSkill` 完全一致（同样的 `min-charge` 门控、同样的友军保护跳过、同样的扇形筛选）——**直接继承 `MeleeSmashSkill` 并在伤害计算前插入一步条件判定**是最省事的实现方式：
   ```java
   public final class EchoConsumeSkill extends MeleeSmashSkill {
       // type() = "echo_consume"
       // 在 target.damage() 之前：
       //   double mult = 1.0;
       //   if (states.armorBreak(uuid) != null || states.markBonus(uuid) > 0
       //       || target.hasPotionEffect(SLOWNESS) || target.getFreezeTicks() > 0) mult = echoBonus;
       //   damage *= mult;
   }
   ```
   若 `MeleeSmashSkill` 是 `final`（当前是 `public final class`），实现时把它改成 `public class` 并把 `execute` 内的"伤害计算段"抽成 `protected double applyBonus(...)`。这是唯一的代码结构改动，其余全是新增。
2. **条件定义（四选一，命中即满足）**：
   - `CombatStates.Mark` 未过期（易伤标记，来自 `mark_apply` / `special_shot_toggle` / 带 `mark-bonus` 的弹体）；
   - `CombatStates.ArmorBreak` 未过期（破甲，来自 `armor_break`）；
   - 目标身上有 `SLOWNESS` 药水效果（减速，来自丝线 / 冰系 / 咆哮 / `pull` 的 `decelerate`）；
   - 目标 `getFreezeTicks() > 0` 或身上有冻结留下的 `SLOW` 极高等级（来自 `freeze-ticks`）。
   > 之所以把"减速"也算作条件，是因为减速是本文档里最容易达成的前置（多个角色的常态左键就能挂），这让**低门槛组合的加成偏低**（×1.4）、**高门槛组合的加成偏高**（×1.6）——见 4.2 表。
3. 加成只作用于**本技能的直接伤害**，不作用于弹体的范围衰减之外的目标；不改变击退 / 减速 / 点火等附加效果。
4. 触发时动作栏提示"兑现！"（`skill.echo-consume`），并额外播放 `hit-particle`，让玩家明确知道条件命中了。
5. `echo-bonus ≤ 1.0` 时该参数等同关闭（不放大），便于运维一键回退。

| 参数键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `damage` | double | 12.0 | 基础伤害 |
| `range` | double | 3.2 | 扇形半径 |
| `angle` | double | 50.0 | 扇形半角（度） |
| `knockback` | double | 0.35 | 击退 |
| `min-charge` | double | 0.9 | 攻击蓄力门控（与 `melee_smash` 一致） |
| `echo-bonus` | double | 1.5 | 条件满足时的伤害倍率 |
| `echo-ticks` | int | 100 | **动作栏提示**的持续时长（不影响前置状态本身，前置状态由施加方决定） |
| `slow-duration` / `slow-amplifier` | int | 0 / 0 | 附加减速 |
| `particle` / `hit-particle` / `sound` / `miss-sound` | string | CRIT / CRIT / BLOCK_ANVIL_LAND / ENTITY_PLAYER_ATTACK_WEAK | 表现 |
| `display` | string | 兑现 | 动作栏 / 冷却条上的技能名 |

> **不要调用 `fx().castHeavy(...)`**：现有 `castHeavy` 只在 `shockwave` 与 `mirror_burst` 两个"原地大范围"技能里被调用（`ShockwaveSkill:44`、`MirrorBurstSkill:37`）。`echo_consume` 是瞬发单点爆发，加 title 演出会拖慢手感，也会和"条件命中"的动作栏提示抢位置。

> **弹体形态**：`projectile` 也可以带 `echo-bonus`（组合 6 的真实之铳就是这么用的）。那种情况下不必新类型，只要给 `projectile` 的**结算器**（`ProjectileListener`）加同一段条件判定即可 —— 见 7.3。

### 5.4 `deploy_zone` —— 场地技能（治疗场 / 丝网陷阱）

**行为**：在施法位置生成一个**静态领域**，持续 `duration-ticks`，每 `period-ticks` 结算一次，对区域内目标施加效果。

**判定细节**

1. 记录一次施法快照：`center`（施法瞬间的玩家位置，**不跟随玩家**）、`radius`、`owner UUID`、`expireAt`。用 `plugin.scheduler().runTimerTask(..., period-ticks, period-ticks)` 驱动。
2. 每个结算周期遍历 `center` 周围 `radius` 内的 `LivingEntity`：
   - **敌方**（非队友、非旁观者）：`damage` 伤害 + 刷新 `slow-duration`/`slow-amplifier` 减速；
   - **友方**（含自己，`ally-radius > 0` 时）：`heal-per-second × (period-ticks/20)` 治疗 + 首次进入时给 `absorption` 吸收（同一玩家同一领域只给一次，用 `Set<UUID>` 记录）；
   - PVE 模式下敌方为月人、友方为全部玩家，逻辑不变（沿用 `MeleeSmashSkill.isProtectedTeammate` 的同队判定）。
3. **友伤护栏**：治疗只对"同队或 PVE 同队"生效；PVP 下对敌队不治疗。治疗量按周期摊分，`heal-per-second 1.0` + `duration-ticks 120` → 总计 6.0 血（约 1/3 条命），低于复活回血 `kill-heal 6.0` 的量级。
4. 领域不破坏地形、不生成实体、不落方块，**纯逻辑 + 粒子环**（每周期用 `fx().particle` 画一圈，复用 `MirrorBurstSkill.drawRing` 的写法）。
5. 玩家死亡 / 退出对局 / 房间销毁时，其名下的领域立即结束（`clear(uuid)` 里一并清理）。

| 参数键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `radius` | double | 3.5 | 领域半径 |
| `duration-ticks` | int | 120 | 持续时长 |
| `period-ticks` | int | 20 | 结算周期 |
| `damage` | double | 0.0 | 每周期对敌伤害 |
| `slow-duration` / `slow-amplifier` | int | 0 / 0 | 每周期刷新减速 |
| `heal-per-second` | double | 0.0 | 友方每秒治疗 |
| `absorption` | double | 0.0 | 友方首次进入的吸收量 |
| `ally-radius` | double | 0.0 | >0 时领域对友方生效 |
| `particle` / `sound` | string | END_ROD / BLOCK_TRIPWIRE_ATTACH | 表现 |

### 5.5 `summon_ally` —— 召唤忠犬

**行为**：在施法者前方 `spawn-distance` 格生成 `count` 只受控生物，存活 `duration-ticks`，自动攻击附近敌人（排除队友与召唤者）。

**判定细节**

1. 用 `world.spawnEntity(loc, EntityType.valueOf(entity))`；只允许 `WOLF` / `CAT` / `PARROT` / `SNOW_GOLEM` 等**中立或可驯服**类型，`ConfigValidator` 侧复用 `resolveEntityType` 校验（拼错就点名）。
2. 生成后立刻：
   - 打 PDC 标记 `summoned_owner`（UUID）与 `summoned_expire`（毫秒时间戳），复用 `PDCKeys` 的新增键；
   - `setTamed(true)` + `setOwner(spawner)`（狼/猫），`setTarget(最近敌人)`；
   - `setCustomName(name)` / `setCustomNameVisible(true)`；`setRemoveWhenFarAway(true)`；
   - 通过 `addPotionEffect(SPEED, -1, speed-amplifier)` 与 `addPotionEffect(INCREASE_DAMAGE/STRENGTH, ...)` 体现 `damage` 参数（原版狼攻击力不可直接改，用力量药水等级换算：`damage 3.0` → 力量 I）。
3. **护栏**：
   - 召唤物**不参与计分**（击杀它不给分）：`MatchListener` 里判断 PDC 标记直接 `return`；这是必须的，否则会出现"刷狗刷分"。
   - 队友与召唤者不能伤害它：`CombatListener` 里对带 `summoned_owner` 的实体的 `EntityDamageByEntityEvent`，若攻击者与 owner 同队则取消。
   - 对局结束 / 房间销毁 / 玩家退出时，遍历该房间世界内带 `summoned_owner` 的实体统一 `remove()`（挂在 `GameRoom` 的清理钩子上）。
   - 同一玩家同时最多 1 只：施法前检查该 owner 是否已有存活召唤物，有则先 `remove()` 再生成（`count > 1` 时同样只保留本次召唤的这一批）。
4. 45 秒冷却、12 秒存活 ⇒ 覆盖率约 27%，等效输出增量约 `3.0 × 12 / 45 = 0.8 DPS`，远低于任何一把武器的直伤，属于"牵制与视野"而非"伤害来源"。

| 参数键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `entity` | string | WOLF | 实体类型名（`EntityType`） |
| `count` | int | 1 | 数量（硬上限 2） |
| `health` | double | 12.0 | 最大生命（同时设置当前生命） |
| `damage` | double | 3.0 | 换算为力量药水等级的攻击力 |
| `duration-ticks` | int | 240 | 存活时长 |
| `speed-amplifier` | int | 1 | 速度药水等级 |
| `spawn-distance` | double | 2.0 | 生成在施法者前方的距离 |
| `name` | string | 忠犬 | 显示名（支持 MiniMessage，例如 `<gold>忠犬</gold>`） |
| `particle` / `sound` | string | CLOUD / ENTITY_WOLF_GROWL | 表现 |
