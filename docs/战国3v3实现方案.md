# 竹取合战 · 战国 3v3（三局两胜）实现方案

> 依据 `prompt.txt` 的需求编写。**本文档只做设计，不含代码改动**；确认后再进入实现。
> 已确认的决策见第零节，未确认的留白见第十三节。

---

## 零、需求摘要与已确认决策

### 0.1 一句话需求

新增一个**独立**的 `SENGOKU_3V3` 游戏模式：3v3、三局两胜；每小局用"上下路箭楼 → 击破器 → 攻陷敌方天守阁"决出胜负；场地中央持续刷小兵，击杀攒能量放必杀技。

### 0.2 已确认（用户拍板）

| # | 决策 | 影响 |
| --- | --- | --- |
| 1 | **新模式独立**，现有 PVP / PVE 完全不动 | 房间制按 `mode` 分流；回归风险最低 |
| 2 | **地图由用户自建** | 代码侧只负责点位定义、划区工具与逻辑；验收标准第 1、2 条的地图部分由用户保证 |
| 3 | **跳跃台用 TP** | 实现最稳，10 秒内必然抵达；弹射作为可配备选 |
| 4 | 击破器：**所有职业均可操作**、**不可破坏**、**不可丢弃**、**重新占领箭楼后自动生成** | 无需职业白名单逻辑（配置仍留白名单键，默认全开） |
| 5 | **必杀技占用现有 Q 槽** | 不新增按键，无冲突风险 |
| 6 | **保留跨局战绩** | `stats.yml` 的击杀 / 拆家等跨局累计不动，小局重置只清战场状态 |
| 7 | **配置拆成多份文件** | 见第九节；点位复用现有 `arenas.yml`，文案复用现有 `messages.yml` |
| 8 | **天守阁是纯方块结构** | 只需拦截方块破坏与爆炸，无需处理实体/方块实体 |
| 9 | 牛鬼 = **尸壳**（`HUSK`）、虾兵蟹将 = **卫道士**（`VINDICATOR`） | 见 3.2 |
| 10 | 小局时限 **8 分钟**（可配） | 超时判箭楼数多者胜，持平平局重开 |
| 11 | 必杀技**先给全员一个统一默认**，可改 | 先不逐角色设计；`sengoku-energy.yml` 里留出逐角色覆盖的位置 |

### 0.3 击破器的实现方式（我方决定，理由见 4.2）

**拾取携带 + 走到敌方天守阁范围内自动读条**。

## 一、总体架构

### 1.1 与现有模式的关系

```
RoomManager（不动）
   └─ GameRoom（加 1 个轻量钩子）
        └─ SengokuSession（新增：小局编排）
             ├─ TowerManager        箭楼归属 + 守卫刷新
             ├─ TowerCaptureManager 铜钟交互 + 读条占领
             ├─ KeepManager         天守阁状态（无敌 / 可攻陷）
             ├─ SiegeBreakerManager 击破器（生成 / 携带 / 读条）
             ├─ JumpPadManager      跳跃台（TP）
             ├─ MidMinionManager    中地小兵
             └─ EnergyManager       能量槽 + 必杀技
```

**为什么不把 round 塞进 `GameRoom`**：`GameRoom` 已经 81.9 KB，承担着 PVP 与 PVE 两条线的完整生命周期。三局制是新模式专属需求，独立成 `SengokuSession` 后：

- 现有 `Phase` 语义完全不变（`WAITING/STARTING/CAGED/PLAYING/ENDING` 仍然表示**一个小局**的生命周期）；
- `GameRoom` 只需新增**一个**回调点（小局结束时通知 session，而不是直接 `endMatch` 销毁房间）；
- 将来若要给 PVP 也加多局制，可以复用同一个 session 抽象。

### 1.2 小局编排层 `SengokuSession`

职责：

1. 持有 `GameRoom` 引用与小局比分（`redWins` / `blueWins`）；
2. 驱动"小局开始 → 进行 → 结束 → 重置 → 下一局"；先到 2 胜结束整场；
3. **小局重置**：清箭楼归属、击破器、跳跃台、小兵、Boss、玩家位置与临时状态（**不动** `stats.yml`）；
4. 整场结束时走原有 `endMatch` 收尾（世界回收等）。

### 1.3 组件挂载点

`GameRoom` 在小局开始时挂载 `SengokuSession`，小局结束（`Phase.ENDING`）时回调 session；session 决定"还有没有下一局"：

- 有 → session 内部重置战场并让 `GameRoom` 重新进入 `CAGED → PLAYING`（**不销毁房间**）；
- 无 → 放行原有的 `endMatch`。

## 二、小局状态机与胜负判定

### 2.1 小局流程

```
WAITING ──满人──> STARTING ──> CAGED ──> PLAYING ──┬─ 击破器命中天守阁 ──> ROUND_END
                                                  ├─ 小局超时            ──> ROUND_END
                                                  └─ （无其他结束条件）        │
                                                                              ▼
                                        ┌──────── 还有下一局？ ────────┐
                                        │ 是：重置战场 → CAGED → PLAYING │
                                        └ 否：END（整场结束，走 endMatch）
```

### 2.2 小局胜负条件

| 条件 | 结果 |
| --- | --- |
| 击破器在敌方天守阁范围内读条完成 | 该方**立即**赢下本小局 |
| 小局超时（默认 8 分钟，可配） | **箭楼占领数多者**胜；持平则本局**平局**（双方都不加胜场，重开本局） |
| 双方人数不足（掉线兜底） | 沿用现有 `understaffed-grace-seconds` 逻辑 |

> **为什么超时判箭楼数**：箭楼是地图控制权的唯一客观指标，且与小局主线（箭楼 → 击破器）同源。判平局重开是为了避免"龟缩 8 分钟"成为有效战术。

### 2.3 整场胜负

先赢 **2** 小局者赢得整场（`best-of` 可配为 3 / 5）。

## 三、箭楼占领系统

### 3.1 箭楼定义

- 地图上、下路各 **1** 座（共 2 座，可配）；
- 每座箭楼包含：**占领区**（`CuboidRegion`）、**铜钟位置**（`Location`）、**牛鬼刷新点**、**虾兵蟹将刷新点**；
- 归属：`NEUTRAL` / `RED` / `BLUE`，**可被反复易手**（不像现有基地只能拆一次）。

### 3.2 占领前置：清空守卫

箭楼附近有守卫，**必须先清空**才能敲钟：

| 单位 | 规格 |
| --- | --- |
| **牛鬼** | 中型头目，单只，载体 **`HUSK`（尸壳）**；血量 / 伤害 / 速度按 `sengoku-towers.yml` 配置 |
| **虾兵蟹将** | 6~10 只，载体 **`VINDICATOR`（卫道士）**；围绕箭楼巡逻（复用 `MinionTypes` 的巡逻 / 仇恨参数） |

> 实体名走 `VersionAdapter` 解析，写错只告警不崩服；两种实体都可加 `model-data` 做材质区分。

守卫被清空后**进入冷却**（默认 20 秒，可配）才重新刷新——避免"刚清完立刻又刷出来"导致无法占领。

### 3.3 铜钟交互

| 步骤 | 说明 |
| --- | --- |
| 触发 | 玩家右键铜钟（`PlayerInteractEvent`，拦截原版钟的使用） |
| 校验 | 守卫已清空？己方是否有正在读条的玩家？敌方是否也在读条？ |
| 读条 | `tower.capture-seconds`（默认 5 秒），ActionBar 显示进度条（复用 `SkillManager.progressBar`） |
| 中断 | 离开占领区 / 死亡 / 被击退出去 → 进度归零（可配为"缓慢衰减"） |
| 成功 | 归属切换为己方 → 播报 + 粒子 + 音效 → 触发 3.5 |

**瞬时模式**：`tower.capture-mode: instant` 时右键即占领（保留读条逻辑但时长置 0），用于快速对局或调试。

### 3.4 不可同时占领（核心规则）

`prompt.txt` 第 9 条：**双方同时读条时，双方都不推进**。

实现：每 tick 统计每座箭楼的读条玩家集合。

```
redAttackers   = 属于 RED 且在占领区内的玩家
blueAttackers  = 属于 BLUE 且在占领区内的玩家

若 redAttackers 非空 且 blueAttackers 非空：
    → 双方进度都不变（并给两边 ActionBar 提示"争夺中，双方进度停滞"）
否则：
    → 只有非空的那一方推进
```

> 注意这与现有 `BaseCaptureManager` 的关键差异：现有基地是"只有敌方能在区域内推进"（单向），箭楼是"**双方都能推进，同时在场则互锁**"（双向争夺）。因此**不能直接复用** `BaseCaptureManager` 的进度模型，只复用它的读条 / 播报 / 衰减等外围写法。

### 3.5 占领后的连锁效果

占领任一箭楼后，**同时**发生两件事（对应 `prompt.txt` 第 11、13 条）：

| 效果 | 位置 | 归属 |
| --- | --- | --- |
| 生成**大将击破器** | **敌方**天守阁门前 | 占领方可用 |
| 生成**跳跃台** | **己方**天守阁门前 | 占领方可用 |

两者都遵循"**重新占领后自动生成**"（用户确认第 4 条）：每次归属变更为己方时重新检查并补齐；若击破器已被消耗，则重新生成。

## 四、天守阁与击破器

### 4.1 天守阁状态

| 状态 | 说明 |
| --- | --- |
| **不可攻陷（默认，始终）** | 直接攻击天守阁无效——拦截 `BlockBreakEvent`、爆炸（`EntityExplodeEvent` / `BlockExplodeEvent`）等一切破坏路径 |
| **可攻陷（仅击破器读条时）** | 击破器持有者进入范围并读条完成 → 本小局胜利 |

> 按 `prompt.txt` 第 5 条，天守阁**从来不能被直接打掉**，只能通过击破器。所以"无敌"不是阶段状态，而是**永久性质** + 一条专用胜利通道。

天守阁是**纯方块结构**（已确认）：代码只按 `arenas.yml` 里的区域判定 + 拦截方块破坏/爆炸，**不涉及实体或方块实体**。胜利是逻辑判定，**不修改地形**——每小局都要重置，真拆了建筑就回不来。

### 4.2 击破器：为什么选「拾取携带 + 到点自动读条」

三个候选方案的对比：

| 方案 | 稳定性 | 实现成本 | 致命问题 |
| --- | --- | --- | --- |
| **(b) 推动 / 发射实体** | ❌ 差 | 中 | 掉落物被推动极易卡进方块、地形、台阶；不同客户端延迟下位置不同步；"不可破坏"难以保证（火/爆炸/岩浆/仙人掌/虚空） |
| **(c) 右键投掷** | ❌ 差 | 高 | 需自写抛物线 + 命中判定；"不可丢弃"与"投掷"语义直接冲突；打偏后物品丢失无兜底 |
| **(a) 拾取携带 + 到点读条** | ✅ **好** | **低** | 无 |

**选 (a) 的三条理由**：

1. **完全复用已有基础设施**。`prompt.txt` 第 39 条要求"绑定物品不可被他人捡走或放入箱子"——插件里**已经有这套 PDC 护栏**（`items.soulbound`、`PDCKeys.owner`、绑定物不可入箱/不可被捡）。击破器只要打上同样的标记，三条约束（不可破坏 / 不可丢弃 / 不可被抢）**零新增代码**即可满足。
2. **不依赖物理引擎**。物品在背包里是绝对稳定的；读条阶段玩家站着不动，与现有占点逻辑同构。
3. **中断与兜底天然清晰**。携带者死亡 → 击破器原地掉落（带标记，己方仍可捡）；服务器重启 → 由"重新占领箭楼"或小局重开补齐。

### 4.3 击破器流程

```
占领箭楼（归属变为己方）
   └─> 在【敌方】天守阁门前生成掉落物「大将击破器」
         · 材质/名称/发光/粒子可配
         · 带 PDC：sengoku_breaker + owner(队伍) + instance
         · 不可破坏（拦截 ItemDespawnEvent / EntityDamageEvent / 火焰 / 爆炸）
         · 无限存活（Paper setUnlimitedLifetime）
         ↓ 玩家走近或右键拾取
      进入背包（soulbound 标记：不可丢弃 / 不可入箱 / 不可被敌方捡走）
         ↓ 携带者进入【敌方】天守阁范围（可配半径，默认 4 格）
      自动读条（ActionBar 进度条，arm-time-seconds 默认 8 秒）
         · 中断：离开范围 / 死亡 / 掉线 → 进度归零，物品留在原地
         ↓ 读满
      本小局立即判定己方胜利
```

**补充规则**：

- 携带者**死亡**：击破器以掉落物形式落在死亡点（保留队伍标记），己方其他人可捡；
- 击破器**同一时间每队最多 1 个**（避免占领两座箭楼刷出两个）；
- 击破器**不可被敌方拾取**（PDC 校验）；
- 若击破器因任何原因消失，**重新占领任一箭楼**即自动补齐（用户确认第 4 条）。

## 五、跳跃台

### 5.1 行为（已确认：用 TP）

| 项 | 设计 |
| --- | --- |
| 生成位置 | 己方天守阁门前（占领任一箭楼后出现） |
| 触发 | 站上跳跃台方块 / 踩压力板 → 传送（默认），或按配置改为弹射 |
| 目标 | `nearest`（最近的**己方**已占领箭楼，默认）/ `specified`（指定箭楼序号） |
| 冷却 | `jump-pad.cooldown-seconds`（默认 3 秒，防连点） |
| 表现 | 传送前后粒子 + 音效；落地给短暂免摔 / 抗性（可配） |
| 可用时机 | **阵亡复活后即可用**（`prompt.txt` 第 13、53 条）——不限制状态 |
| 10 秒抵达 | TP 天然满足；文档里以"生成点 → 箭楼"的实际距离 + TP 延迟说明 |

### 5.2 弹射模式（可配备选）

`jump-pad.mode: launch` 时改为给予初速度（`power` / `upward`）+ 缓降 + 免摔窗口。**默认不用**，但保留配置键，便于将来调手感。

## 六、中地小兵与能量必杀

### 6.1 中地小兵

| 项 | 设计 |
| --- | --- |
| 载体 | 复用**月人**（用户明确允许"可以把月人改名，或者直接用月人"） |
| 生成区 | 场地中央独立刷新区（`sengoku.yml` 的 `mid-minions.regions`，用现有选区工具划） |
| 上限 | `max-alive`（默认 40），达到上限停止刷新 |
| 频率 | `interval-seconds` + `per-spawn`，并按 `shard-tick` 分片（每 tick 只处理 1/N 个区域） |
| 行为 | 巡逻 + 仇恨（复用 `MinionTypes`）；**允许被绕过**（不强制清兵） |
| AI 简化 | 可配关闭部分寻路（`ai-simplify`），降低大量实体时的服务端压力 |
| 击杀收益 | 给击杀者加能量（见 6.2）；**不计入对局积分**（避免刷小兵赢比赛） |

**性能**：小兵数量可能很大，方案里强制三条——实体上限、分片刷新、按距离分级 tick（远离玩家的小兵降低 AI 频率）。

### 6.2 能量槽与必杀技

| 项 | 设计 |
| --- | --- |
| 能量来源 | 击杀中地小兵（`energy.per-minion`，默认 +8；精英更多） |
| 上限 | `energy.max`（默认 100） |
| 显示 | ActionBar 或 BossBar 副条（`energy.display: actionbar`） |
| 释放 | **占用 Q 槽**（用户确认第 5 条）：能量满时按 Q 释放必杀技并清空能量 |
| 必杀技内容 | 与**角色**绑定（`sengoku.yml` 的 `energy.ultimate.<characterId>`），未配置的角色用默认必杀（范围击退 + 伤害） |
| 与模式切换的冲突 | **能量满时 Q 优先放必杀**，模式切换在此期间不可用 → ActionBar 明确提示"能量已满：Q 释放必杀"；能量未满时 Q 保持原有模式切换行为 |
| 跨小局 | 能量**每小局清空**（战场状态的一部分） |

## 七、场地点位与划区流程

### 7.1 新增点位（`ArenaDef` 扩展）

| 点位 | 数量 | 用途 |
| --- | --- | --- |

## 九、YAML 配置（拆分为 5 份 + 复用 2 份）

### 9.1 拆分总览

`prompt.txt` 给的 8 个文件名是"例如"级别的示意。实测下来有两项不该新建文件，其余按「谁改、多久改一次」重新切分：

| 文件 | 内容 | 谁改 | 频率 |
| --- | --- | --- | --- |
| **`sengoku.yml`**（新） | 对局骨架：小局数、时限、超时判定、重置策略、天守阁 | 服主 | 低 |
| **`sengoku-towers.yml`**（新） | 箭楼：占领模式与时长、互锁、守卫刷新、牛鬼 / 虾兵规格、铜钟 | 平衡 | 中 |
| **`sengoku-siege.yml`**（新） | 击破器 + 跳跃台 | 平衡 | 中 |
| **`sengoku-minions.yml`**（新） | 中地小兵（含性能相关键） | 平衡 / 性能调优 | 中 |
| **`sengoku-energy.yml`**（新） | 能量槽 + 必杀技 | 平衡 | 中 |
| `arenas.yml`（**复用**） | 天守阁 / 箭楼 / 铜钟 / 牛鬼点 / 虾兵点 / 中地小兵区 / 跳跃台 **点位** | 管理员划区 | 建图时 |
| `messages.yml`（**复用**） | 全部播报文案 | 文案 | 低 |

三处"不新建"的理由：

- **`map.yml` 不建**：点位在现有架构里本就属于场地定义（`ArenaDef` → `arenas.yml`），平时是"选区锄划一下存进去"。新建 `map.yml` 会变成两套点位体系，选区和校验都得写两份。
- **`teams.yml` / `respawn.yml` 不单列**：队伍人数、复活延迟这些已在 `config.yml` 的 `match.*` / `waiting.*` 里，战国模式直接继承；只有**本模式独有**的键才进 `sengoku*.yml`。
- **`messages.yml` 不新建**：已存在。插件有"新键自动回填默认值"的机制，老配置文件不会因为缺键而显示成键名。

## 十二、已知限制与后续扩展

### 12.1 已知限制

1. **地图需用户自建**（已确认）。代码只保证逻辑；若点位缺失，`doctor` 会点名但不会自动补图。
2. **不修改地形**：攻陷天守阁是逻辑判定，天守阁建筑本体不会被拆——这是刻意的（每小局要重置，拆了就回不来）。
3. **击破器在服务器重启后不会自动恢复**，需重新占领箭楼触发（兜底路径已设计）。
4. **小兵 AI 是简化的**：为性能牺牲部分寻路质量，可能出现"小兵绕不过障碍"。
5. **必杀技占用 Q 槽**：能量满时无法切换武器模式，这在设计上是取舍（已在你确认的第 5 条内）。
6. 三局制**只对战国模式生效**，PVP / PVE 仍是单局。

### 12.2 后续扩展建议

- 小局之间的**中场增益**（例如赢下小局的一方下一局开局多一个箭楼耐力加成）；
- **观战增强**：观众可切换视角看箭楼归属与击破器位置；
- **必杀技独立按键**（若将来愿意引入第五输入槽）；
- **地图轮换**：多张战国地图随机或投票选择（`ArenaDef` 已是多场地结构，天然支持）；
- **战力统计**：把"箭楼占领次数 / 击破器携带次数"写进 `stats.yml` 的长局统计。
